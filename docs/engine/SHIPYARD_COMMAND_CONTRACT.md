# Shipyard commands and fleet production

This follows the complete fleet-value/combat-helper gate and the independently verified shipyard-state guard. Use the existing six ship definitions, native sovereign currency, colonies, economies, construction records and explicit resolved shipbuilding capabilities. Do not introduce another writable fleet representation or a second economy store.

## World ownership

`ShipbuildingReadView` borrows const spans of civilizations, stellar systems, construction, shipyards, colonies, economies, fleets, capability sets and optional per-civilization strategic preferences. `ShipbuildingWorld` borrows mutable spans for shipyards, colonies and economies, but a `std::vector<FleetState>&` for the authoritative fleet collection: completion appends to it. Other collections remain const. Build fresh read spans when needed; do not retain fleet references across append. The view converts to the existing `ShipDesignReadView`; no duplicate capability algorithm. Empty preference records mean the source `None`, and the first matching explicit record wins like the established capability adapter.

Value results preserve all source fields: order accepted/message; cancellation assessment can-cancel/active/design/refund/blocker; cancellation accepted/message/refund; completion civilization/fleet/design/message. There is no new UI or timer schema in this gate. Native budget input distinguishes absent from present-empty and uses the existing civilization budget value type if its representation is compatible, not its construction-specific resolution algorithm.

Expose start, read-only cancellation assessment, cancel, demand, automatic order selection, global advance and selected-civilization advance. The seeder is a separate adapter over the same FleetState, not a substitute for completion. Required state validation must happen at each equivalent source QueuedBuilds getter access, not unconditionally at method entry. `PendingBuildCount` deliberately reads the underlying queue count without invoking that guard. Preserve source First/FirstOrDefault/Single distinctions and failure order.

## Accounting and mutation ordering

Start validates civilization; pending cap8; design; construction/capability locks; economy/currency; finite available credits with0.0001 tolerance; stable identity; source population/species. Only then debit actual credit authorization and reserve the design population from the largest owned colony, preserving first-on-tie order. Colony ship250million and outpost8million require another500million left at their source. Record exact source colony and species in the order. Advance the sequence once per accepted order, including queued orders. Reject invalid or exhausted int64 identities without mutating money/population.

Assess cancellation with source guards and lookup order. Detect ambiguous active/queued identity, unknown design, invalid/nonfinite/negative paid quote/progress/population, excessive progress, missing or changed original source ownership/species, population overflow, treasury/refund overflow, and unsafe next promotion. Cancel uses source Single lookups after a successful assessment; duplicate state/economy records can therefore still fail. Resolve currency before mutations. Restore colonists to the exact original colony; refund the paid quote times unconsumed work for active orders and the full paid quote for queued orders. Never return industry. Assessment leaves every input unchanged. Failed commands preserve state except where an explicitly captured source exception occurs after a source mutation; do not silently redesign the baseline.

Advance validates days before automatic orders; zero days returns immediately. Selected advance does not select AI orders. Global advance selects automatic orders first. Skip seeded ancients. No active design skips economy and budget lookup. Consume at most20industry/day and remaining work, according to the source ResolveBudget: absent budgets returns stock as-is; present missing key returns0; present nonfinite entry throws; otherwise min(stock,max(0,budget)). This is intentionally distinct from construction. Preserve Math.Min/Max NaN behavior in out-of-domain source cases; native import hardening is separately documented.

Completion captures reserved colonists/species, creates one fleet, appends it, clears the active order and all reservation fields, promotes the next queued order, then emits one event. Never spend leftover tick time on the promoted order. If promotion's source population guard fails after an append/clear, the fixture must capture the actual partial state and event behavior. Fleet IDs inspect all existing fleets; role counts include inactive vessels. Fleet names, current/home position, propulsion, sensor, cargo and initial combat values must match. Populated colony designs must carry a known species. C# fleet-ID arithmetic can wrap unchecked; native must avoid signed-overflow UB and expose a documented explicit identity-exhaustion rejection at that boundary, not claim wrapped negative IDs as safe imported state.

AI preferences are advisory only. Skip player/ancient/busy civilizations. A preferred missing Scout/Science/Military can be selected; Colony requires expansion permission and no active populated colony fleet and no deferral. Logistics is not an accepted preferred role here. Fallback Scout, then Science at curiosity>=0.60, then eligible Colony. Actual StartBuild still enforces payment, capabilities and population. Never seed artificial fleets just to make AI parity pass.

## Seeder distinction

FleetSeeder.Seed visits WarpCapable civilizations only; EnsureStarterFleets first finds the civilization, then returns only if it already has an active Scout. Ensure does not independently check development stage. It may add a second populated Colony if existing fleets lack an active Scout; preserve the source behavior. Starter scouts use raw design propulsion and null combat, unlike completed ships' effective propulsion and initialized combat. Preserve the authored One/Scout/Pioneer names. The scout is appended before resolving colony population/species. Unknown species can thus throw after adding the scout. Source seeding lacks the order path's explicit finite-population check; distinguish faithful operation parity from a future import gate. Do not reuse completion in a way that changes these defaults or failure order.
