# Shipbuilding dependency and migration contract

Preserve the existing C# shipbuilding rules before connecting native fleet production to the campaign tick. No visual or balance changes belong in this port. Source: Shipbuilding/ShipDesignRegistry.cs, ShipDesignDefinition.cs, ShipbuildingCapabilities.cs, ShipyardState.cs, ShipbuildingSimulation.cs, Models/FleetState.cs and the combat state types it owns.

## First independently testable dependency

Freeze all six ship definitions in registry order, every authored field and prerequisite collection. FleetRole numeric order is Scout, Science, Colony, Military, Logistics. Role fallback must preserve the colony baseline while an explicitly persisted resource-outpost design remains distinct. A persisted design is used only if registered and its role matches. Unknown/empty/mismatched identity falls back exactly as GetForFleet. Invalid role fails usefully; do not create fictional fallback hulls.

Ship design queries read const construction records and explicit resolved capability sets. This adapter is separate from research authority: no replacement of Adaptive Research with prototype technology IDs. Prototype and Adaptive mapping remain future integration dependencies, clearly named in status. Locks combine missing all-capabilities, completed-project requirements, then an optional any-capability clause, in source order and wording. Availability retains registry order and does not infer affordability. Queries must not mutate source collections.

Propulsion prioritizes extended_ftl_range over reliable_ftl. Extended multiplies speed by1.35 and leg/fuel by1.75; reliable uses1.18/1.30/1.35; otherwise preserve prototype. Every descriptive generation string and single-precision sensor scalar remain source exact. Different civilizations cannot leak capability results across query calls.

Prove this dependency with direct actual C# calls, not reimplemented expected formulas. Cases cover all fields in all definitions, null/empty/case-mismatched/unknown/persisted mismatch resolution, all role fallbacks, all/any/project lock combinations including empty custom lists, capability display fallback, precedence and no state mutation. The C# GetForFleet oracle should use actual FleetState even though the narrow native resolver accepts its two relevant fields. Report this as catalog/prerequisite/propulsion parity, never complete fleet simulation.

## Following queue and fleet gate

One authoritative shipyard state per civilization stores a stable order ID, actual paid authorization, work progress and reserved population with species/source colony provenance. Active plus queued pending cap8; IDs have source ASCII validation/max128 and canonical positive int64 sequence parsing. Population-bearing invalid or overflow state must never be silently dropped. Preserve the source defensive queue-access checks with an explicit native validation boundary before every equivalent operation. Native value types need explicit import rejection for unrepresentable null records.

Ordering matters: validate civilization, queue capacity, design and prerequisites, finite treasury/cost, stable order identity, source population and species before debiting either money or colonists. Largest owned colony is selected in stable source order; population must cover ship cost plus500million. Colony ship250million and sealed outpost8million remain actual reserved population, not UI counters. Cancellation assessment is read-only, checks unique order identity/accounting/return source/refund overflow and safe next promotion. Cancellation refunds actual authorization by unconsumed fraction, restores reserved population to the same still-owned species-compatible source and never refunds consumed industry. Failure must not mint credits or abandon colonists.

Native FleetState must represent every current persisted field, including transit waypoints/local movement, mission flags/revision, survey/settlement work, freight cargo, fuel, population, optional compact combat state, optional tactical loadout and important-vessel history. Do not silently omit tactical fields or substitute an incomplete placeholder fleet in a claimed full port. Newly built ships use the exact initial combat profiles and source defaults; ship design, combat profile and role are separate identities. Completion consumes at most20industry/day, transfers reserved population/species to one actual new fleet, emits one event, clears reservations and promotes without spending leftover time on the next order.

Full shipbuilding has selected and whole-world advance variants. Preserve source AI role preferences, missing-role bounds, expansion and colonization deferral; preferences never bypass affordability, prerequisites or population authorization. AI decisions read fleet ownership/activity; player and ancient worlds are skipped according to source. Freeze source budget handling separately from construction: the existing shipbuilding ResolveBudget is not identical, so do not casually share a 'fixed' helper. Imported malformed budgets/state must be distinguished from ordinary tick behavior and tested for matching failure order.

Fleet creation uses home-system position and identity, next fleet ID across all existing fleets, role counts including inactive vessels, correct player/AI names and outpost-specific names, effective propulsion, cargo capacity and initial combat state. Prove identity exhaustion safely without C++ signed-overflow UB. Save-v16 import/export and battle simulation remain separate gates until explicitly ported; the current native package remains headless and does not replace the playable Godot build.
