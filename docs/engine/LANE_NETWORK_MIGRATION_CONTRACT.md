# Native interstellar lane graph boundary

Source authority is `Exploration/InterstellarLaneNetwork.cs`: astronomical conversions, lane Connects/Other, FleetRouteMetrics.Measure, and InterstellarLaneNetwork.Build/FindShortestRoute. There is no public neighbor or route-validation API to invent. This is interstellar stellar geometry, distinct from the already migrated economic logistics graph; do not reuse that graph's cost, permission, or tie-breaking rules.

## Ownership and caching decision

Use a campaign-owned `InterstellarLaneNetwork` with an immutable copied geometry snapshot, analogous to the existing native LogisticsRoutePlanner ownership. Its constructor copies system IDs and StarPosition values without eagerly building geometry. `build()` lazily produces canonical lanes; `find_shortest_route(origin, destination, maximumLegRange, optional permitted IDs)` rejects nonpositive/NaN range before lazy construction, matching the source early return. Return lane views only while their owner lives; routes are owned vectors. An explicit reconstructed/move-assigned graph replaces geometry after edits or loading. Do not use raw source-vector addresses as cache identity or silently retain external spans.

Cache unrestricted route trees by origin and exact range, with the source 64-tree clear-before-add policy. Evaluate each supplied permitted-ID set afresh; absent and present-empty are different. Fuel, ownership, survey state, mission acceptance and refueling are never cached. Owner-thread query access is explicit, following LogisticsRoutePlanner. The headless campaign owner will rebuild the graph when geometry changes; the UI must never own authoritative routes. Source cache mutation fixtures compare a deliberately rebuilt native graph with the changed source list. Also test reuse with changing permission contents/ranges on the same graph. Lazy build must publish a complete successful snapshot; reject invalid geometry cleanly rather than preserving a partially built cache.

## Geometry and path semantics

Use existing physical distance helpers, preserving legacy float 2D versus optional double-depth geometry. Sort systems by ID. Build the minimum-distance connected backbone from the lowest ID, retaining the source 1e-9 tolerance and explicit first-ID/second-ID tie order, then add each node's three nearest neighbors ordered by squared distance and ID. Canonicalize undirected endpoints and emit ascending endpoint pairs with exact physical lengths. Do not use a complete graph or a different Delaunay algorithm. Empty/single inputs have no lanes; duplicate IDs on a nontrivial graph fail with the source category/message. Nonfinite geometry is outside the existing native distance-import contract and must fail cleanly with an explicitly identified native boundary, not hang an oracle on the source sentinel bug.

Shortest route rejects absent endpoints only after validating range/building graph. A permission set missing either endpoint returns empty. Visit unprocessed nodes by distance then system ID, traverse canonical adjacency in source order, accept lanes up to range+1e-9, and update a predecessor only for candidate < current-1e-9. The returned route includes origin and destination; an allowed origin==destination returns a one-node route. Unreachable routes are empty. Preserve zero-length links, exact and near ties, 2D/depth geometry and input permutation behavior. Infinity is a valid unrestricted range. Do not alter topology based on fleet fuel or player knowledge here.

## Remaining route and conversions

Metric conversions retain the authored constants 3.26156 light-years/parsec and 149597870.7 kilometres/AU. Lane Other throws for an unrelated system; Connects is a pure predicate.

FleetRouteMetrics.Measure returns zero legs/distance immediately when final destination is absent, before building the ID dictionary. Otherwise use stored waypoints when nonempty, else the destination. Initialize previous from current system if present and previousChartPosition from the actual fleet position. A valid warp origin and first target contribute the remaining fraction of the physical first leg, using clamped progress, then continue from that target. Missing waypoints are skipped without advancing prior position. Later legs use float chart distance when previous is absent or both depths are absent; otherwise use physical depth-aware distance. Count each accepted waypoint even for coincident positions. This query does not include local gate distances, mutate the fleet, infer exploration, debit fuel, or finish a mission.
