# Adaptive Research foreign-technology parity validation

Gate 057 ports the immutable foreign-technology catalog, sparse per-civilization
assessment/package support, and the research-side runtime. The native runtime
borrows one stable `AdaptiveResearchAuthority` and one stable catalog. It owns
support in a runtime-local weak table keyed by the civilization state's private
identity token. State moves preserve identity, state copies receive a fresh
identity, and separate runtimes never share support.

The retained fixture is generated by the actual C# implementation. It records
the complete canonical catalog projection, exact catalog input bytes and SHA-256
digests, catalog scratch fingerprints before and after every load, complete core
and foreign state before and after every operation, typed results, and exact
managed exception type/message pairs. The replay covers 29 sequential public
runtime commands, a partial package-acquisition failure after evidence insertion,
the unchecked `Int32` assimilation-stage wrap boundary, 8 reflected source state
writer/query operations, and 18 malformed catalog inputs.

One duplicate JSON property case is retained as explicit source-only metadata.
`System.Text.Json` enumerates the duplicate property and the source dictionary
rejects it, while the current native DOM parser collapses duplicate object keys.
Generic JSON syntax and operating-system file diagnostics are outside exact
message parity; authored catalog validation and the retained JSON-kind failures
are compared exactly.

The native-only probes verify equal civilization IDs remain independent, runtime
tables remain independent, state move construction/assignment preserves support,
state copy assignment and same-address replacement obtain fresh support, runtime
moves preserve support addresses, and mutating calls own aliased string/span
inputs before replacing support records. Native signed revision overflow is a
defined rejection rather than C# unchecked overflow.

The maintained native target `stellar_research_foreign_tests` is Windows-only because its fixture hashing uses CNG and links bcrypt. Production code has no Windows dependency. Both isolated Debug and Release C++23 builds passed `/W4 /WX`, with 29 sequential runtime commands, 17 replayed malformed catalog cases and one explicit source-only case, 8 low-level operations and 17 native lifetime/alias probes.
