# Native fleet state dependency

This gate follows the paid construction migration and is required before real shipyard completion. It preserves current game data and combat initialization without claiming fleet travel, battle simulation or save-v16 parity. The ship-design contract and `fleet_role.hpp` in this draft directory are already frozen.

## Representation and source authority

Create `fleet_state.hpp` with one value-owned `FleetState` matching every field/default in `src/Game/Simulation/Models/FleetState.cs`. Use the existing `Vec2` single-precision XY for strategic fleet position and all three local-transit points; preserve the separate transit phase, origin/target/final mission destination and ordered remaining waypoints. Keep every hold/return/revision/reconnaissance/settlement/freight/fuel/population field and its exact optionality. IDs are signed32 like the source; future allocation must guard overflow. Do not infer mission completion from an intermediate lane waypoint. Do not add extra mutable UI state.

Fleet state owns optional compact `FleetCombatState`, optional `MassiveCombatLoadout`, and optional `MassiveVesselState`. These are complete typed values, not an opaque dropped JSON blob or a partial fleet pretending full persistence. Preserve independent role, ship-design ID and combat-profile ID. Default construction must match actual C# defaults, including active true, strategic speed22, leg360, fuel capacity/current1000, sensor135, empty route and no reserved population/species. This representation alone is not a game-save importer.

Create `combat_state.hpp` with the exact four `CombatProfileDefinition` values and `FleetCombatState` fields/defaults from Combat/CombatProfiles.cs and Combat/CombatState.cs. Military order enum numeric order is Hold, Defend, Attack, Retreat. Functions are `combat_profile_catalog`, `find_combat_profile`, `get_combat_profile`, `default_combat_profile_id`, `create_initial_fleet_combat_state`, and `ensure_fleet_combat_state(FleetState&)`. Preserve unknown/blank profile fallback and role-specific defaults. Ensure mutates only the source combat fields: clamp durability, nonnegative cooldown/retreat, repair invalid order to Hold, and clear disengagement when current system differs. A missing/unknown profile resets the whole compact combat state. Preserve C# NaN propagation where applicable; do not silently replace imported invalid data with a new gameplay policy.

Include complete tactical value types from Combat/Massive/MassiveCombatEquipment.cs and MassiveCombatState.cs: `MassiveCombatLoadout`, `MassiveWeaponGroup`, `MassiveModuleState`, and `MassiveVesselState`. Weapon enum Beam/Kinetic/Missile/PointDefense/ElectronicWarfare, module enum Reactor/Engine/Sensor/WarpDrive/WeaponControl/PointDefense/ElectronicWarfare/WarpInterdictor retain source numeric order. All single-precision properties, equipment IDs/counts/conditions/flags and named-vessel history survive copying. No formation/battle aggregate is part of this gate.

Port only the actual helper/validation operations attached to these required types: `massive_loadout_from_legacy`, `warp_interdictor` with defaults900range/72strength, and explicit validation functions for loadout, weapon, module and important vessel. Validation bounds/messages/order come from the C# methods. The module-range bound is2000, derived from existing combat engine SpatialCellSize500 times4; this constant does not claim that engine is ported. Source gaps such as an unvalidated scalar must be documented distinctly from native import hardening; never change oracle fixtures to bless a new rule. Avoid native integer-overflow UB in count/mass aggregation; reject out-of-domain inputs explicitly if C# checked arithmetic would throw.

Expose `economic_fleet_projection(std::span<const FleetState>)` in `fleet_state.hpp` using the existing `EconomyFleetState`: copy civilization, role and active status in source order. It is a detached read projection and never another writable authoritative fleet store. Do not seed fake active ships or consume UI markers.
