# Strategic self-state and runtime composition boundary

After the intent/provider and observer-local planner gates, port the actual self-state builder, director and scheduled runtime. Supporting sources are `Combat/CombatReadiness.cs`, the prototype classes in `Construction/ConstructionCapabilities.cs` and `Shipbuilding/ShipbuildingCapabilities.cs`, and `AI/CivilizationStrategicInputBuilder.cs`. The composer sources are `AI/CivilizationStrategicDirector.cs` and `AI/CivilizationStrategicRuntimeCoordinator.cs`.

## Capabilities and combat readiness

Prototype construction queries the first matching technology state for the requested completed technology ID. Prototype shipbuilding maps spacecraft construction to orbital_industry and experimental interstellar transit to prototype_warp_drive; every other capability is false. Do not accidentally grant reliable or extended transit from similarly named legacy technologies. Keep these adapters explicitly separate from future Adaptive Research materialization. Query interfaces must retain the first-match and missing-technology behavior before translating capabilities to the existing native ship/construction input records.

Combat readiness is a read-only own-force calculation, distinct from the mutating combat summary method. Validate the civilization, visit active owned fleets ordered by ID, and preserve the exact counter and floating-point summation order. Missing or unknown combat profiles are evaluated as pristine role defaults without writing them back. For a known profile, nonfinite persisted durability becomes zero before clamping. Unknown order values become Hold for this read. Disengagement applies only when its optional system matches CurrentSystemId, including the source's null equality. Combat-effective armed strength excludes retreats, disengaged ships and nonpositive hull. Preserve durability, hull-scaled offense, repair deficit, count fields and ratio defaults. This view cannot be exposed as exact enemy intelligence.

## Own-state builder

Require civilization, economy, technology and construction, in that order, then query logistics. Build population species from positive owned colonies plus the civilization's species, distinct with ordinal comparison. Ask the actual exploration planner for each active owned Scout/Science fleet in ID order and stop at the first supported candidate; use its 64-candidate bound. Known colony opportunity examines only fully surveyed unoccupied bodies with biology viable for an available population. It does not reuse the colony mission planner's fleet reservation or price checks; those are different source questions.

Query spacecraft construction then experimental transit, and require the orbital_shipyard project for interstellar shipbuilding. Military capacity counts all active Military-role fleets as the source does, while strength uses read-only combat readiness. Desired military fleets depend on colony count and capability. Available legacy research requires no active research and a nonempty authoritative available-tech query. Retain the exact source clamps and evaluation sequence when returning own strength, supply coverage, industry reserve, science throughput and opportunity flags. All injected logistics, capability and exploration calls need typed ordered observations and failure scenarios. Do not derive foreign facts from authoritative rival state.

## Director and retained runtime

The director validates world, traits and knowledge, rejects future knowledge before checking civilization membership, builds self-state, requests the cached plan and builds intent. Invalidate/remove/clear forward to its planner. A returned review owns all records and must survive later cache changes.

The runtime owns a director, two published-preference providers, knowledge provider, nullable campaign seed, strategic days and next-review map. Validate finite nonnegative days first. A changed campaign seed resets clocks, schedules and providers/director before accepting that call's delta. Unlike the full campaign coordinator, this method does not return early for zero days: due civilizations can still be reviewed. Add days, derive source floor/max tick, then visit nonplayer, non-seeded-ancient civilizations ordered by ID. Skip only those strictly before their scheduled review. Build observer knowledge, reject future observations, review with force=false, publish industry then ship preference, update next-review tick and append result. Later failure leaves earlier publications, clocks and cache effects intact. Reset clears everything. Do not reconstruct the runtime on each campaign step.

The empty-knowledge compatibility provider is the source default for isolated simulations. It is not integrated diplomacy. Reject or explicitly bound nonrepresentable accumulated native tick conversions instead of invoking C++ undefined behavior; include full partial-state and subsequent-call evidence for that boundary.

Compare every output field, callback sequence and source mutation boundary. The full campaign coordinator can compose these ports only after their source-backed validation passes.
