# Gate 087 Galaxy16 aggregate proposal

`GalaxyPayloadV16Dto` is a complete owned typed representation of the current galaxy payload and its detached-envelope metadata. It composes the maintained gate DTOs and retains nullable collection presence where source order depends on it. `game_version` and `saved_at_utc` are opaque owned text in this gate; the later player/JSON wrapper owns DateTimeOffset parsing and clock injection.

`FreshCampaignState` receives two appended owned fields in the accompanying draft patch: `optional<CampaignMassiveEncounter> active_combat_encounter` and `optional<CampaignDeveloperProvenance> developer_provenance`. Provenance is explicit: null means Player state, while a present value retains Developer `tools_used`. No second world owner or forced-safe Boolean is introduced.

Capture takes a mutable world because the actual source validates and may materialize encounter formation counts, then fleet capture may normalize combat records before later projection failures. It first checks requested payload provenance, then follows the source validation and projection order. The returned aggregate owns every nested value.

The native state also carries a geometric core used by rendering and movement. C# has only the authoritative named landmark at this boundary. Capture therefore rejects a populated geometric core that has no matching named `galactic_core` (directly or in generation metadata). Fresh-factory attachment of persisted metadata and its named landmark remains required integration work before native fresh worlds can be saved; this gate does not silently discard that core or invent metadata.

Restore accepts exactly format 16 as the native supported-boundary policy; this does not claim the C# service rejects its historical formats. It follows the current branch through systems, bodies and safe Sol upgrade, current civilizations/knowledge and the documented no-civilization branch, empty fleet preservation, authoritative surface collections, technology/construction/shipyard fallbacks, combat-state materialization, metadata/core validation and agreement, geometric-core derivation in the source landmark coordinate space, and final catalog/reference validation. It never calls `seed_fresh_campaign` as a repair and never manufactures generation metadata. A restored raw galaxy payload has no developer provenance; only the future validated Developer wrapper may attach it.

Successful restore returns the owned world with opaque envelope values. Nullable list presence is retained; nullable elements that an already-maintained nested typed DTO cannot express remain named parser boundaries rather than silently covered cases. Nested adapter exception categories and inner details propagate unchanged. Historical galaxy formats, Player17/Developer wrappers, JSON parsing, DateTime validation, file writing, research/diplomacy composition, and tactical stepping are outside this gate.
