# Construction migration contract

Next dependency gate after logistics and industry allocation. Migrate the preserved paid construction path, surface placement and upgrades. Keep the current game rules and wording; balancing and visual expansion remain paused. Source owners are `Construction/ConstructionSimulation.cs`, `ConstructionState.cs`, `ConstructionRegistry.cs`, `ConstructionCapabilities.cs`, the command/timer/validation portions of `SurfaceConstruction.cs`, and `Economy/SovereignCurrency.cs`.

## State and dependency boundary

Use one authoritative native `ConstructionState` per civilization: completed project IDs with set semantics and stable insertion order; optional active project; progress; actual authorization amount; ordered queue of paid project records. Keep the existing economy-only construction projection as an explicit detached read model built from these states. Do not maintain two writable completed-project stores. Persisted legacy authorization zero must remain zero: cancel cannot mint historical payments.

Construction reads an explicit resolved capability set per civilization. The later research adapter owns mapping established knowledge/capabilities to this set. Do not silently replace Adaptive Research with legacy technology rules. Parity fixtures can supply the same answers through a small C# `IConstructionCapabilityView`; also exercise the actual prototype adapter where relevant. The frozen project registry retains all six definitions, IDs, authored descriptions, costs, requirements, categories, upkeep and production. Project lock names are the preserved registry names (Orbital Industry, Warp Field Control), not guessed research labels.

Mutable world spans are valid only for an owner-thread command/tick. Read views contain const spans. Command handlers return the actual accepted/message/refund records. Queries do not debit, enqueue or change timers. Preserve source validation order and its documented command-side queue promotion; do not invent blanket transaction rollback where the source promotes the head before rejecting a later order. Malformed imported state is validated before normal play; failed imports are never committed.

## Currency formatting

Port all four sovereign denominations and unknown-species fallback exactly, including UTF-8 symbols, normalized budget conversion, K/M/B/T thresholds, optional code, clamped negative amounts, signed per-day formatting and first-civilization lookup. This is the existing local-denomination display, not a new interstellar credit market. Freeze invariant English output for portable native diagnostics and C# fixtures; future localized UI belongs to the localization adapter. Exercise values around each threshold and rounding midpoint, signed zero, negatives, nonfinite and very large values. C# custom `0.##` numeric formatting is not automatically equivalent to C++ fixed stream rounding: prove it or explicitly translate the relevant behavior. Invalid inputs must not invoke undefined conversions in native formatting.

The narrow shared formatter is `detail/legacy_number_format.hpp`. It preserves the custom-format precision and decimal rounding described by the pinned [.NET 8 implementation](https://github.com/dotnet/runtime/blob/v8.0.0/src/libraries/System.Private.CoreLib/src/System/Number.Formatting.cs); the existing .NET MIT notice remains packaged. Standard grouped `N0` formatting is a separate path because it uses different rounding semantics. Native and actual-C# fixtures must agree on each supported message format.

IDs use local max+1; overflow fails with a useful command result, never signed-overflow UB. Authorization checks credits/materials with existing .0001 tolerance and debits once. Ordinary placement charges credits and creates an incomplete site; industry is spent by later ticks. Module/hub upgrades charge both costs immediately and complete after funded elapsed work, keeping old production until completion. Cancellation, demolition, repair, enabled status and operating priority preserve source behavior and all cost/message fields. Do not change the source surface cancellation's50% current authorization-cost refund as part of migration; document it distinctly from project unused-authorization refunds.

Validate every imported surface record: unique positive IDs, legal placement, finite progress within cost and IsComplete consistency, priority0..1, condition0..1, hub timers, legal pending upgrade and positive matching timer, battery storage within capacity+.0000001. Retain source order/error categorization. Existing malformed/null collections unsupported by native value types get explicit adapter rejection, not invented parity claims.

## Surface timer semantics

Industry demand includes incomplete sites only and preserves source summation order. `advance_surface_construction` requires finite nonnegative budget/days; committed upgrades advance first even when ordinary industry budget is zero. Their work is days times clamped operating funding. Ordinary construction demand caps each site at30 industry/day and shares available budget proportionally across colony-ID/building-ID order. Completion tolerance1e-7; exact cost stored on completion. Ordinary stock is debited only by actual aggregate spend. Do not silently normalize invalid negative stock in the port if the existing source does not; distinguish import validation from tick parity. Upgrade completion replaces type, sets progress to upgraded cost and condition1, clears pending/timer; hub increments when remaining <=1e-9. Disabled buildings and original power-storage contents retain source transition behavior.

## Civilization projects and queues

Start/queue/cancel use current paid authorization checks, capabilities and prerequisite projects. Eight queued slots; duplicates and unavailable/complete/locked orders reject in source order. Queue promotion is FIFO and head blocking is visible; no skipping invalid heads. Cancel active refunds actual authorization times clamped unconsumed industry fraction, with no industry refund; queued refunds recorded authorization. Promotion never charges twice. Unknown/missing states preserve useful failure semantics.

Project advance accepts finite nonnegative days; zero is a no-op. Whole-world advance ensures automatic AI orders, selected-civilization advance does not. Ancient civilizations are skipped. Available budget is finite clamped to stock, missing supplied budget means zero; null budgets mean stock. Surface/project shares retain source proportional arithmetic, surface advancement occurs first, project then spends at most30/day. Completion tolerance .0001 emits one ordered event and promotes the next order but does not spend remaining time on it during the same loop. AI picks affordable available projects through the same paid command, source score and stable cost tie ordering. Available-project queries preserve registry order and source semantics around active/queued projects.

Expected-error catches surround only the real operation, never parsers or assertions. Native comparisons run outside catches. Keep Release and Debug validation plus relocated package proof. This gate does not claim whole campaign ticks, research/fleet/save-v16 or graphical parity.
