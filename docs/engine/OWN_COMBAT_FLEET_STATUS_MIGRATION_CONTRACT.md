# Own combat fleet status migration contract

`OwnCombatFleetStatusBuilder.Build` is a read-only exact-own query. The native
entry point accepts immutable civilization and fleet spans, rejects an unknown
civilization with the source message, filters inactive and foreign fleets, and
returns active owned fleets ordered stably by fleet ID.

Every returned scalar and computed property follows
`OwnCombatFleetStatus.cs`. Missing, blank, or unknown combat profiles use the
pristine default for the fleet role without creating persisted combat state.
Recognized profiles use clamped finite shields, armor, hull, cooldown, and
retreat progress. Unknown military-order values present as Hold. Attack-target
and defend-system details are exposed only for their matching normalized order.
Disengagement requires the persisted flag and nullable system equality.

The summary remains the canonical `CombatReadinessCalculator` projection. The
native port extracts its internal per-fleet projection into
`detail::read_fleet_combat_readiness`, which is shared by the existing summary
and the new per-fleet view. Its profile and persisted-state pointers are used
only during the query; the public result owns strings and scalar values.

The fixture is generated by the actual C# builder. Each case records complete
civilization and fleet input, before/after snapshots, all summary and per-fleet
fields, every computed property, and exact source errors. The C# null-galaxy
case is a source-only observation because the native typed view cannot represent
a null world. `FleetState.TacticalLoadout` remains outside the native import
boundary; fixtures require it to be null and retain nondefault tactical vessel
history separately.

The 46 source cases cover every role and known order, unknown order and combat
profile fallback, stable duplicate IDs, inactive/foreign privacy, negative and
nonfinite values, epsilon edges for firing and hull damage, retreat ratios,
nullable disengagement, an unarmed profile, and mixed aggregate state. Strict
Release and Debug builds use `/W4 /WX /fp:precise`; their compile and run logs
are stored below the matching draft configuration directory.
