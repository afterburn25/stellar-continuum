# Funded economy and colony operations migration

Frozen headers: `core/include/stellar/core/campaign_economy.hpp` and `core/include/stellar/core/colony_operations.hpp`. Sources are the preserved `Economy/EconomySimulation.cs`, `ResourceOutpostOperations.cs`, `ResourceDepositProfile.cs`, `Construction/SurfaceConstruction.cs` (GetEnvironmentalWearMultiplier and AdvanceCondition only), `ConstructionRegistry.cs` (economic data projection), and `Generation/ConstructionSeeder.cs` (completed-project economic projection only).

This gate implements the complete current EconomySimulation credit-flow/advance/storage calculations and their existing surface-wear/resource-outpost dependencies. It does not implement the whole campaign tick orchestrator, construction authorization or project timers, research spending, fleet simulation, logistics, or full saves. Fleet/construction inputs are explicit read-only economic projections. Later authoritative owners must supply them; never infer active fleets from UI markers. Role enum maps the five current C# roles by name/value and preserves fallback cost for other values. Completed project IDs are set-valued; do not multiply effects by inventing duplicates. Six project economic profiles come from authored registry values, with ancient seeding completing the original registry list.

The world view borrows civilization/body/project/fleet collections for a call. The caller owns lifetimes. Advances write only supplied colonies/economies, on the simulation owner thread. Read functions never mutate them. Preserve original list traversal, first-match lookups, numeric order and units: simulation deltas are DAYS despite legacy fields named PerSecond. Do not change tax rates, per-population industry, support policy or gameplay balance during translation.

Credit flow preserves actual staffed/workforce-demand labor interpretation, population/infrastructure/stability clamps, fractional small-colony administration, services, exact-species habitat burden reduction, active fleet operations, orbital and surface upkeep, and optional previous recorded research costs. Base advance excludes recorded research spending to avoid double charging; current research controller remains a later owner. Funds pay opening arrears before current obligations; current funding fraction throttles newly generated industry/science but permits existing stored reserves. Preserve Last* ledger fields and accrueLegacyScience false behavior.

Advance order matters: calculate opening credit flow; settle obligations; for each colony calculate opening population factors and species turnover; apply funding-dependent condition wear; allocate surface power for the same delta; advance battery storage; compute colony industry/science; advance resource outposts; then change ordinary colony population using actual sustenance/reserves, supported logistic headroom, species growth factor or unsupported decline. Apply project effects and funding before ledger accrual. Preserve outpost population behavior, completed project multipliers, and separate ApplyIndustryStorageCaps semantics (including preserved prior above-cap reserves). No fabricated whole-game step follows this API.

Surface wear preserves exact body+system match, missing-body neutral multiplier, environmental thresholds, two-decimal MidpointRounding.AwayFromZero, .002 unfunded daily wear and source funding tolerance; only complete/enabled buildings degrade. No repair command is added.

Outpost deposit hash uses explicit uint32 wrapping; retain physical-grade/accessibility and material naming, reserve clamps, finite funding validation, original defaults when body/economy/deposit is absent, fabrication-based physical storage even if a building is offline, and extraction based on actual powered output. Preserve finite deposits, capped free storage, remaining-reserve initialization and updates, status priority and invariant-culture percent text. Capture expected text directly from C# for midpoint percentages instead of guessing formatting. Respect original early-return/error behavior; additional input validation, if necessary, must be explicit and tested against the source difference, not silently treated as parity.

Authoritative oracle requirements: actual original C# calls and immediately cloned before/after states. Cover all project profiles/fleet role costs; normal/ancient construction defaults; all credit-flow components, active/inactive fleets, unknown project fallback, research inclusion/exclusion, ordinary/outpost distinction, Earth/Luna/Mars and multiple species; funded/part-funded/depleted/arrears-repayment/recovery; no double research charge; science accrual on/off; resource shortages/reserve depletion/population decline and excess capacity growth; completed project effects; empty/full/legacy preserved industry storage; real damaged/unstaffed/unpowered buildings and batteries; multi-day and repeated steps; wear thresholds and fractional funding; all deposit material/grade branches, no deposit, depletion, full storage, multiple fabricators, default funding and invalid funding; full state nonmutation/read-only and mutation comparisons. Test scenarios must assert they actually activate shortage/extraction/depletion/funding conditions. Compare all fields and sets, with documented float/decimal tolerance and bounded exception matching outside comparison assertions.

Ownership: operations worker owns `core/src/colony_operations.cpp` and its actual-C# oracle/fixture/native consumer; funded-economy worker owns `core/src/campaign_economy.cpp` and actual-C# oracle/fixture; separate comparison worker owns its native consumer.
