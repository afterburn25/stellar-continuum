# Gate 045 validation

`ResearchApplicabilityOracle` runs the retained C# loader and lookup method under invariant culture. Every generated malformed case is an exclusively owned scratch copy; its before/after SHA-256 fingerprint is recorded. Production calls alone are caught, and projection/fingerprinting occurs after the catch.

The native catalog owns every ID and definition, borrows the base catalog only while loading, and exposes const spans plus allocation-free `noexcept` hash lookups. It compares all 14 canonical definitions and their order, scope ordinal values (Civilization=0, PopulationOrSpecies=1), case-sensitive lookup, mutable flags, exact semantic and lookup messages, duplicates, counts, and missing-property, wrong-property-type, parser, and file boundaries separately. The fixture-only SHA-256 implementation uses Windows CNG with checked statuses and scoped handles; no Windows dependency enters the Core implementation. Runtime eligibility and mutable research state are deliberately outside this gate.

The approved 26-row fixture has SHA-256 `1EC2E478FE714488261799F08FE7CC06E531AA06595E1B9A9A8A0A558173D2C7`. Strict MSVC Debug and Release builds use `/W4 /WX /permissive- /fp:precise /utf-8` with object and PDB outputs under the ignored draft build directories. The original 23-row fixture passed both strict configurations. After review added null, missing and nonstring catalog identifiers, the maintained Windows build and focused CTest replayed the corrected 26-row fixture: 5 success, 11 semantic, 2 lookup, 1 parser, 1 file, 3 missing-property, and 3 wrong-property-type cases. The prior strict draft logs cover 23 rows, not 26. The Windows-only CNG fixture consumer is conditionally registered under WIN32; the Core catalog remains portable.
