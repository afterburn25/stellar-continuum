Reviewed on 2026-09-13: `CampaignStatePersistenceService.cs` (425 lines) and `DeveloperCampaignPersistenceService.cs` (144 lines), with the format declarations in `CampaignSaveService.cs`. The latter's full 2045-line galaxy conversion/validation remains a separate review gate.

## Version boundaries

The current PLAYER campaign format is **17**, wrapping the authoritative **galaxy format16**, Diplomacy snapshot, and Adaptive Research campaign schema2 (which nests standalone research schema5). Earlier coordination shorthand "save-v16" referred to the galaxy payload and must not be interpreted as the complete player save. Native foundation checkpoints and standalone research snapshots do not establish player campaign compatibility.

Galaxy-only formats1..8,10,12,16 restore through the galaxy service, then create fresh research state and an EMPTY DiplomacyState. Never infer contacts, treaties, wars, claims or trust from omniscient galaxy state. Campaign wrappers9/11/13 normalize galaxy versions8/10/12 respectively. Wrapper15 requires explicit inner version8/10/12; wrapper17 requires exactly16. Both15/17 require authoritative AdaptiveResearch payload; older wrappers create research profiles. All wrappers require strict Diplomacy snapshot validation and galaxy-reference checks.

## Capture and atomic write

PrepareSave validates galaxy/diplomacy/research presence, exact Player-versus-Developer provenance, then finite nonnegative simulation time. It captures and validates Diplomacy and its galaxy references BEFORE detached galaxy capture. Require inner format16. Research capture uses the passed research campaign's own runtime association. Build detached envelope format17 with GalaxyFormatVersion16, Diplomacy and AdaptiveResearch. Prepared payload must be immutable with respect to subsequent simulation mutation; capture and JSON/write durations are diagnostics, not simulation state.

WritePrepared validates nonblank path, nonnull prepared state and exact Player/Developer payload kind before serializing. Existing source writes indented, case-sensitive JSON. Atomic writer creates exclusively owned sibling GUID .tmp, writes UTF8 without BOM, flushes writer then file to disk, and either replaces the old primary (rotating .bak) or moves for a new file. Repair save after recovering a known-good backup preserves that backup once; ordinary saves resume rotation. Cleanup may remove only the temp file created by that operation. Preserve the prior primary/backup on write failure. Native implementation must provide the corresponding filesystem guarantees and failure evidence before claiming compatibility.

## Developer envelope

Inner Campaign must be one of9/11/13/15/17. Recursively reject nested DeveloperSession, DeveloperFormatVersion, Mode or ToolsUsed anywhere inside the canonical campaign. Restore normal campaign first, then attach DeveloperSessionState with the preserved ToolsUsed flag. Never allow a Developer prepared payload or file to pass the Player save path.

Developer load progress .03 read, .14 validated, nested player progress mapped to .14+fraction*.83, final .98. Existing source creates an exclusively owned staging file and deletes only after ownership is established. Native codec may consume the same detached JSON through a shared internal decoder, but must preserve validation order, mode separation, returned state and diagnostics; avoid adding a second permissive decoder.

Share current campaign capture internally between Player and Developer persistence using an explicit payload kind and exact provenance check. Do not temporarily clear Developer provenance on the live world, or copy the world solely to bypass the Player guard: capture has observable validation mutations and failure ordering. Only the validated Developer envelope attaches provenance after restoring its canonical inner campaign. A future prepared-save owner must retain its payload kind privately so Player and Developer writers cannot be interchanged accidentally.

## Composition and durable-write boundaries

Engine 0.1.38 integrates the remaining typed planetary, knowledge and cross-reference adapters and the legacy recovery helpers. The next gate composes current galaxy16 capture/restore before adding historical version dispatch and the Player17/Developer envelopes. This keeps complete current-state recovery reviewable without claiming that a typed adapter is already a compatible JSON save reader.

`CampaignSimulationState::campaign()` retains the owned `FreshCampaignState`, including generation metadata. Append the owned active encounter and explicit optional Developer provenance to that existing state; do not introduce a second world that can diverge. Capture borrows this world mutably because source validation can materialize legacy encounter counts and fleet combat state. The prepared result must own its nested data before asynchronous writing begins. Only the validated Developer wrapper attaches Developer provenance on restoration.

The generic Engine writer receives bytes and filesystem paths, with no Core or JSON dependency. It owns an exclusive sibling temporary file, writes all bytes, flushes to disk, then replaces or moves it. Backup preservation is a per-write option; the caller resumes normal rotation after repairing a primary from its known-good backup. Serialization and save-mode validation precede this byte writer.

Windows replacement has documented partial-failure outcomes; a failed call does not always mean the original path is intact. Retain surviving recovery data and report primary, backup and temporary paths for ambiguous failures. Do not claim power-loss certification from ordinary write tests. `ReplaceFileW` does not support its write-through flag; use an explicit file flush. Sources: [ReplaceFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew), [FlushFileBuffers](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers).

Test process-local serialization separately from cross-process races and path aliases. The same physical file can have case, short-name or hard-link aliases; lexical path normalization alone does not establish file identity. Before claiming concurrency coverage, specify and test the identities actually serialized. Failure injection supplements real filesystem tests and must not replace locked-file, backup and relocation checks.

Generation metadata timestamps currently remain opaque strings: the JSON boundary must validate and preserve DateTimeOffset offsets and fractional precision. Generation metadata retains entered/internal seed, generator/art profile versions, creation timestamp, system count, shape, stellar/planet/habitability options, guaranteed nearby worlds, other/ancient civilizations, hazards, starting development, difficulty, optional species and anomaly frequency, plus the optional landmark. Capture deep-clones the active encounter: battle clock/pending seconds/counters, formations and their orders, movement/damage/heat/power/warp state, weapons/modules, cohorts and important vessels, missile salvos, ordered events, vessel bindings, engagement evidence and reconciliation state. The live tactical encounter suspends strategic time in its existing owner. Active-encounter recovery requires a dedicated native battle/encounter state and subsequent deterministic tactical continuation; it is not covered by the strategic combat port or074 per-ship power.

Source reference validation checks the active encounter first. Its participant/formations and bound vessel inventory must conserve initial ships; engagement pairs must be unique, canonically ordered and refer to known formations. Combat intelligence is then limited to4,096 records, unique by observer/fleet, with an existing fleet, nonnegative observer and finite nonnegative power/day plus nonblank evidence. Runtime074 intentionally preserves source operations which may be rejected by this later persistence invariant; saving must reject bad state clearly rather than normalizing it silently.

Restore preserves an empty fleet list for every format3 and later. Surface-aware formats12/16 require authoritative nonempty colonies/economies and exactly one economy for each civilization; no reseeding missing authoritative state. Earlier fleet/colony/economy/technology/construction/shipyard migrations use their original per-version thresholds and population reservation behavior. ExactSol upgrades occur before civilization/fleet conversion, wrapping unsafe upgrade exceptions. Capture and final restore both perform planetary and reference validation, including parent cycles and cross-system references, surface capacity/environment/reserves, tactical identity, role-compatible designs, fuel/cargo limits, route endpoints and valid local-work orders. Preserve first-error order in the eventual actual-source fixture.

The galaxy-only historical SaveCore still uses a simple .tmp/.bak path; the canonical campaign wrapper's reviewed exclusive GUID-temp writer is the boundary to reproduce for new native player/developer saves. Do not mistake the older helper for the wrapper's stronger ownership and recovery behavior.

Fleet restore validates transit enum/progress/local float positions before creating the fleet, resolves reserved population species with the original format thresholds, preserves all route/work/cargo/combat fields, and restores legacy range/fuel defaults only under their original conditions. Pre-format8 destination bodies are ignored. An old in-flight fleet with no explicit transit phase becomes InterstellarWarp while retaining its strategic position; its target is the first planned route entry or destination fallback. Warp without a target and local transit without a current system fail before CombatProfileRegistry.EnsureState. General reference validation then rejects invalid role/design/loadout/fuel/route state. Future parity must test these first-error boundaries and the subsequent continuation of an already travelling fleet.

Shipyard restore and capture have deliberately different invalid-state policies. Restore permits negative legacy population only when no authorization, identity, species or colony-source metadata accompanies it, then clamps that empty legacy value to zero. It may discard unknown or overflowing orders only if doing so cannot discard people, paid authorization or order identity; otherwise it fails. Active/queued legacy IDs are synthesized using accepted queue order, and canonical sequences must remain below NextOrderSequence. Source capture rejects negative population and preserves the same refund/population conservation guarantees, including the difference between raw queue index and accepted queue capacity. These are owned assets and people: do not replace these rules with unconditional filtering or truncation. Test limits, legacy ID collisions, unknown designs, refund metadata, reserved species and exact material-progress tolerance.

Knowledge restore preserves the historical distinction between legacy KnownSystemIds (all facts known when no survey records exist) and newer detected/partial/full survey records. Partial progress is clamped to the source open interval, and exploration of the hidden core without its access unlock fails first. Core access, explored state and known civilization facts must survive restoration without revealing additional systems.

## Native session and codec boundaries after 0.1.39

The current typed aggregate restores the same complete source payload and runs a subsequent nonbattle native integrated step as a smoke check. That continuation checks initialization and phase execution; it is not an additional full next-step C# parity fixture. The lower maintained coordinator gates provide the existing simulation comparisons. Player17/Developer wrappers, the JSON codec and historical aggregate restoration remain separate milestones.

The caller must not feed a restored live tactical encounter into strategic advancement. Source `IntegratedMain._Process` (lines 64–78) calls `RunMassiveCombatFrame` first and runs the strategic frame only when it returns false. `Main.MassiveCombat.cs` (lines 95–121) takes ownership of strategic pause, advances or reconciles tactical time, and restores the previous strategic speed on reconciliation. A completed tactical frame still consumes that frame. The future native session owner must reproduce this routing, menu pause and restored-encounter handling before exposing native player load; attaching the encounter to a world does not implement this lifecycle.

The generic Engine `FixedClock` does not replace either game clock. Core strategic time uses the source `SimulationClock` bounded-day/backlog policy and resume-speed state; tactical time uses `MassiveCombatClock` real seconds and its separate allowed speeds. On loading an active encounter, source resets tactical speed to paused. A native host must not silently start the restored battle or advance strategic time while it owns the pause. Autosave scheduling uses strategic simulation days, preserves the distinct success and failure retry deadlines, and should prepare at most one save attempt when a frame crosses a deadline.

Tactical continuation is a separate authoritative port of `MassiveCombatEngine`, followed by `CampaignMassiveCombat` reconciliation. Preserve its 0.1-second ticks, retained pending seconds and bounded catch-up; ordered formation traversal; pre-movement spatial index; power/heat, target, movement, interdiction, missile, attack and withdrawal phases; and event ordering. Reuse the existing owned tactical state and validation rather than building parallel state for presentation. Exact source save/restore/next-tick fixtures must include an in-flight missile, damaged cohorts, pending warp, and eventual campaign reconciliation before native player saves with an encounter are considered resumable.

The new persistable fresh-campaign factory attaches the actual supported FullGalaxy profile and consistent named/geometric core to a newly generated world. It does not invent metadata for a loaded world. Its caller supplies creation time; the eventual JSON boundary validates DateTimeOffset rather than changing generation semantics.

Direct Galaxy JSON deserialization must process known duplicate properties in source order. Collapsing a JSON object into a last-value dictionary before typed conversion can hide an invalid earlier value that System.Text.Json would reject. Distinguish absent required members from explicit nulls, preserve case sensitivity and integer widths, and use the actual serializer options without globally enabling fields. Source-accepted reference nulls that a current native DTO cannot represent must produce an explicit native representability error with a path; they must not be reported as matching source JSON failures or silently discarded. Such exclusions prevent a claim of complete save compatibility until resolved.

The campaign wrapper uses a different source entry point: `JsonNode.Parse(...).AsObject()` followed by root member access, rather than direct Galaxy deserialization. Prove duplicate-member behavior at that entry point independently before reusing the direct codec policy. Developer envelope validation additionally enumerates and rejects duplicate or unexpected envelope fields explicitly.

Player JSON loading must preserve interleaved decoding and world validation. After whole-document syntax and root/format checks, source decodes and validates Diplomacy, checks the inner Galaxy version, decodes and restores Galaxy, validates Diplomacy world references, then decodes and restores research before constructing Diplomacy state. Eagerly decoding every nested DTO before these steps can report a later malformed research field before an earlier invalid diplomatic or galaxy state. A shared internal restoration implementation may accept staged decode operations, but must not duplicate authoritative validators or restore the same world twice just to recover this ordering. Test competing failures through the actual campaign load entry point.

Typed Player restoration must retain simulation day, game version and save timestamp alongside its stable runtime, world, research and Diplomacy owners. Host activation is separate: snapshot research while its borrowed runtime is stable, destroy the old borrowing research state, then transfer the runtime and reconstruct the active owner. Host clock conversion errors belong to activation, which must complete on a candidate before replacing the live session. Pure persistence must not add a host clock reset absent from source load.

For player recovery, retain the difference between `CampaignSessionService.LoadExisting` and `LoadOrCreate`. The former tries primary then backup, reports monotonic progress across fallback, and never generates or writes a replacement on failure. A backup recovery must retain the known-good backup through the first repaired primary write; the generic Engine writer provides the preservation option but the session owns that decision. Prepared saves must own immutable bytes before background I/O and be captured only after the complete bounded simulation step. Saving must not temporarily replace the active world or expose the startup screen.
