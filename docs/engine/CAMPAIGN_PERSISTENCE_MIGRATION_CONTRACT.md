# Campaign persistence migration contract

Reviewed on 2026-09-13: `CampaignStatePersistenceService.cs` (425 lines) and `DeveloperCampaignPersistenceService.cs` (144 lines), with the format declarations in `CampaignSaveService.cs`. The latter's full 2045-line galaxy conversion/validation remains a separate review gate.

## Version boundaries

The current PLAYER campaign format is **17**, wrapping the authoritative **galaxy format16**, Diplomacy snapshot, and Adaptive Research campaign schema2 (which nests standalone research schema5). Earlier coordination shorthand "save-v16" referred to the galaxy payload and must not be interpreted as the complete player save. Native foundation checkpoints and standalone research snapshots do not establish player campaign compatibility.

Galaxy-only formats1..8,10,12,16 restore through the galaxy service, then create fresh research state and an EMPTY DiplomacyState. Never infer contacts, treaties, wars, claims or trust from omniscient galaxy state. Campaign wrappers9/11/13 normalize galaxy versions8/10/12 respectively. Wrapper15 requires explicit inner version8/10/12; wrapper17 requires exactly16. Both15/17 require authoritative AdaptiveResearch payload; older wrappers create research profiles. All wrappers require strict Diplomacy snapshot validation and galaxy-reference checks.

## Capture and atomic write

PrepareSave validates galaxy/diplomacy/research presence, exact Player-versus-Developer provenance, then finite nonnegative simulation time. It captures and validates Diplomacy and its galaxy references BEFORE detached galaxy capture. Require inner format16. Research capture uses the passed research campaign's own runtime association. Build detached envelope format17 with GalaxyFormatVersion16, Diplomacy and AdaptiveResearch. Prepared payload must be immutable with respect to subsequent simulation mutation; capture and JSON/write durations are diagnostics, not simulation state.

WritePrepared validates nonblank path, nonnull prepared state and exact Player/Developer payload kind before serializing. Existing source writes indented, case-sensitive JSON. Atomic writer creates exclusively owned sibling GUID .tmp, writes UTF8 without BOM, flushes writer then file to disk, and either replaces the old primary (rotating .bak) or moves for a new file. Repair save after recovering a known-good backup preserves that backup once; ordinary saves resume rotation. Cleanup may remove only the temp file created by that operation. Preserve the prior primary/backup on write failure. Native implementation must provide the corresponding filesystem guarantees and failure evidence before claiming compatibility.

## Developer envelope

Developer format1 requires exactly DeveloperFormatVersion, Mode, ToolsUsed and Campaign, with no duplicates/extras. Mode must equal Developer exactly and ToolsUsed must be a Boolean. Inner Campaign must be one of9/11/13/15/17. Recursively reject nested DeveloperSession, DeveloperFormatVersion, Mode or ToolsUsed anywhere inside the canonical campaign. Restore normal campaign first, then attach DeveloperSessionState with the preserved ToolsUsed flag. Never allow a Developer prepared payload or file to pass the Player save path.

Developer load progress .03 read, .14 validated, nested player progress mapped to .14+fraction*.83, final .98. Existing source creates an exclusively owned staging file and deletes only after ownership is established. Native codec may consume the same detached JSON through a shared internal decoder, but must preserve validation order, mode separation, returned state and diagnostics; avoid adding a second permissive decoder.

## Current galaxy payload: further source review

Source review on 2026-09-13 covered CampaignSaveService capture/clone (88–203), top-level restore (204–420), planetary/reference validation (1145–1331), and envelope/galaxy DTO fields (1756–1792), plus the metadata record and CampaignMassiveEncounter validation. Further review covered fleet restoration (675–797), shipyard restoration (943–1092), knowledge restoration (1093–1144), and shipyard save invariants (1634–1719). This remains a partial review of the 2,045-line service; other individual historical conversions remain open.

The galaxy16 payload additionally carries optional generation metadata, the optional named GalacticCore landmark, an optional active tactical encounter, and fleet combat intelligence. FreshCampaignState currently has only the geometric core and newly appended intelligence; it does not yet own the complete generation metadata or active encounter. Do not add a save codec which silently drops those fields or treat a native diagnostic JSON as galaxy16. Leadership already has an owned native roster and must preserve insertion order when captured.

Generation metadata retains entered/internal seed, generator/art profile versions, creation timestamp, system count, shape, stellar/planet/habitability options, guaranteed nearby worlds, other/ancient civilizations, hazards, starting development, difficulty, optional species and anomaly frequency, plus the optional landmark. Source validation allows absence for older campaigns but requires nonblank entered seed/version, matching seed and system count, positive count and nonnegative ordinary civilization/nearby-world counts. The named landmark must have the exact stable key, finite float coordinates/radius with positive radius, no star strictly inside radius, and exact agreement between metadata/state landmarks when both exist. Do not regenerate metadata while loading.

Capture deep-clones the active encounter: battle clock/pending seconds/counters, formations and their orders, movement/damage/heat/power/warp state, weapons/modules, cohorts and important vessels, missile salvos, ordered events, vessel bindings, engagement evidence and reconciliation state. The live tactical encounter suspends strategic time in its existing owner. Active-encounter recovery requires a dedicated native battle/encounter state and subsequent deterministic tactical continuation; it is not covered by the strategic combat port or074 per-ship power.

Source reference validation checks the active encounter first. Its participant/formations and bound vessel inventory must conserve initial ships; engagement pairs must be unique, canonically ordered and refer to known formations. Combat intelligence is then limited to4,096 records, unique by observer/fleet, with an existing fleet, nonnegative observer and finite nonnegative power/day plus nonblank evidence. Runtime074 intentionally preserves source operations which may be rejected by this later persistence invariant; saving must reject bad state clearly rather than normalizing it silently.

Restore preserves an empty fleet list for every format3 and later. Surface-aware formats12/16 require authoritative nonempty colonies/economies and exactly one economy for each civilization; no reseeding missing authoritative state. Earlier fleet/colony/economy/technology/construction/shipyard migrations use their original per-version thresholds and population reservation behavior. ExactSol upgrades occur before civilization/fleet conversion, wrapping unsafe upgrade exceptions. Capture and final restore both perform planetary and reference validation, including parent cycles and cross-system references, surface capacity/environment/reserves, tactical identity, role-compatible designs, fuel/cargo limits, route endpoints and valid local-work orders. Preserve first-error order in the eventual actual-source fixture.

The galaxy-only historical SaveCore still uses a simple .tmp/.bak path; the canonical campaign wrapper's reviewed exclusive GUID-temp writer is the boundary to reproduce for new native player/developer saves. Do not mistake the older helper for the wrapper's stronger ownership and recovery behavior.

Fleet restore validates transit enum/progress/local float positions before creating the fleet, resolves reserved population species with the original format thresholds, preserves all route/work/cargo/combat fields, and restores legacy range/fuel defaults only under their original conditions. Pre-format8 destination bodies are ignored. An old in-flight fleet with no explicit transit phase becomes InterstellarWarp while retaining its strategic position; its target is the first planned route entry or destination fallback. Warp without a target and local transit without a current system fail before CombatProfileRegistry.EnsureState. General reference validation then rejects invalid role/design/loadout/fuel/route state. Future parity must test these first-error boundaries and the subsequent continuation of an already travelling fleet.

Shipyard restore and capture have deliberately different invalid-state policies. Restore permits negative legacy population only when no authorization, identity, species or colony-source metadata accompanies it, then clamps that empty legacy value to zero. It may discard unknown or overflowing orders only if doing so cannot discard people, paid authorization or order identity; otherwise it fails. Active/queued legacy IDs are synthesized using accepted queue order, and canonical sequences must remain below NextOrderSequence. Source capture rejects negative population and preserves the same refund/population conservation guarantees, including the difference between raw queue index and accepted queue capacity. These are owned assets and people: do not replace these rules with unconditional filtering or truncation. Test limits, legacy ID collisions, unknown designs, refund metadata, reserved species and exact material-progress tolerance.

Knowledge restore preserves the historical distinction between legacy KnownSystemIds (all facts known when no survey records exist) and newer detected/partial/full survey records. Partial progress is clamped to the source open interval, and exploration of the hidden core without its access unlock fails first. Core access, explored state and known civilization facts must survive restoration without revealing additional systems.
