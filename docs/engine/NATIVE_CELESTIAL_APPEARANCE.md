# Gate 145 — native celestial appearance

This stage closes two visible gaps in the native orbital chart without changing its observer projection, orbital geometry, selection, or simulation.

The implementation follows the preserved presentation in `celestial_star.gdshader`, `stellar_photosphere.gdshader`, `stellar_corona.gdshader`, `SystemSpatialCanvas.DrawSaturnRings`, and `saturn_rings.gdshader`. A surveyed star is an immutable 1024×1024 class-coloured RGBA photosphere and corona. Seeded coordinate warping combines broad, medium and fine noise with small irregular spot groups, avoiding the blocky enlarged surface of the initial 256px candidate. A bounded presentation-clock prominence uses the preserved long-slot birth/growth/fade shape. Black holes receive a separate dark horizon and restrained rim. Reconnaissance-only systems keep the maintained unknown marker and never receive class colour.

Surveyed Saturn uses two immutable 512×512 annular layers. The back layer is submitted before the existing photo-derived globe, and the front layer afterward, so the opaque globe naturally hides the far half while the near half crosses its limb. A narrow complementary-alpha overlap keeps their back-then-front composition equal to the intended annulus opacity outside the globe, avoiding a bilinear-filtering crack without weakening the occlusion. A continuous annulus with broad and fine density variation, a narrow Cassini division, restrained colour, tilt and flattening follows the existing 2D reference without reading as separated wire loops. The trigger is the already observer-filtered `sol_texture_key == "saturn"`; no raw catalog lookup occurs.

The application cache owns at most 18 resources and 32 MiB of generated RGBA pixels. Three detailed stars plus both ring halves occupy about 14 MiB, so ordinary nearby-system switching does not thrash the cache; byte-based eviction still bounds a wider tour. A system/style image is generated only on first use, ring halves are shared globally, and camera pan/zoom changes destination bounds only. External `DrawList` ownership safely extends resource lifetime through submission and downstream texture-cache eviction. One star contributes one image plus at most 36 flare line commands per frame. Ringed bodies contribute two image commands around the existing globe. No decoding or per-frame texture construction is involved.

Focused tests cover transparent bounds, opaque photospheres, black-hole treatment, quiet and active flare intervals, camera-only reuse, distinct seeded surfaces, hard cache pressure, invalid geometry, complementary front/back compositing continuity, command ordering, and ring reuse. This is a sharp functional 2D presentation informed by the preserved design; it does not claim the reference renderer's 3D spheres, volumetric glow, physical shadow maps, atmospheric shells, or close-focus shader parity.

The frozen candidate passed strict `/W4 /WX /permissive-` Debug and Release renderer checks, strict workspace compilation in both configurations, and the actual-source Release system workspace cases. A 120-frame 1280x720 native system smoke used the Vulkan driver, preserved the existing pause/input checks, saved successfully, and reported 12 image uploads (the nine existing planet discs plus one stellar disc and two shared ring halves). Separate 1280x720 and 1920x1080 Vulkan captures render the star and ring layers around the actual photo-derived Saturn globe at inspection scale. Each detail run uploads exactly four immutable images. Final cold generation of the star plus both ring masks measured 17.9–19.4 ms, repeated cache lookup measured 0.0009–0.0011 ms, and the generated cache held three resources in 6 MiB. These bounded observations are evidence from the candidate machine, not a general performance guarantee.

Root integration repeated the actual 720p/1080p system validator after the final complementary-alpha correction. Both views retained selection, pan/zoom/reset, pause and save checks, and uploaded twelve images. Test-scene screenshots do not establish complete game presentation or 60 FPS.
